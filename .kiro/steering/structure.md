# Repository structure

- `packages/core`: schemas, scenario runner, assertions, traces, metrics, experiments, decisions, reports. `src/node` holds Node-only helpers (paths, atomic store, revisions).
- `packages/assets`: style packs, deterministic generators, validation, PNG/WAV encoding, manifest writing.
- `packages/starter`: the shared lean game skeleton both demo games use (fixed-step simulation base, input latch, Phaser scene glue).
- `packages/phaser-adapter`: dev-only `window.__GAMEDNA__` bridge.
- `packages/mcp`: MCP tools, sessions, headless runner, workbench HTTP server.
- `packages/workbench`: React comparison UI.
- `apps/gravity-shift`, `apps/neon-survivor`: the two demo games, each with its own `.kiro/` spec and `.gamedna/` record.
- `power/`: the Kiro Power. `power/server/` is generated by `npm run build:power`; rebuild it after changing `packages/mcp` or `packages/workbench`.
- `docs/`: PRD and project documents. Every Markdown file in `docs/` follows `docs/rules.md`.
- Tests live in `packages/*/tests`, `apps/*/tests` and `tests/` (repository scripts). Browser end-to-end tests live in `tests/e2e/` and run with `npm run test:e2e`.
- `.github/workflows/ci.yml` runs on every pull request; `.github/pull_request_template.md` lists the checks.
