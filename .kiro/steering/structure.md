# Repository structure

- `packages/core`: schemas, scenario runner, assertions, traces, metrics, experiments, decisions, reports. `src/node` holds Node-only helpers (paths, atomic store, revisions).
- `packages/assets`: style packs, deterministic generators, validation, PNG/WAV encoding, manifest writing.
- `packages/starter`: the shared lean 2D game skeleton the two Phaser games use (fixed-step simulation base, input latch, Phaser scene glue).
- `packages/kit`: the GameDNA Kit, reusable 3D game code on three.js (random, loop, input, camera, vehicle, character, world, stage). It imports no workspace package, so `power/kit` can ship it verbatim.
- `packages/phaser-adapter`: dev-only `window.__GAMEDNA__` bridge.
- `packages/mcp`: MCP tools, the engine table (`engines.ts`), command policy (`commands.ts`), the bridge socket server, sessions, headless runner, workbench HTTP server.
- `packages/workbench`: React comparison UI.
- `apps/gravity-shift`, `apps/neon-survivor`: the two Phaser demo games. `apps/ridgeline-racer`, `apps/trail-walk`: the two three.js games built on the Kit. Each has its own `.kiro/` spec and `.gamedna/` record.
- `power/`: the Kiro Power. `power/server/` and `power/kit/` are generated by `npm run build:power`; rebuild after changing `packages/mcp`, `packages/workbench` or `packages/kit`. `power/adapters/<engine>/` holds the hand-written engine adapters that `gd_install_adapter` copies into games.
- `docs/`: PRD and project documents. Every Markdown file in `docs/` follows `docs/rules.md`.
- Tests live in `packages/*/tests`, `apps/*/tests` and `tests/` (repository scripts). Browser and engine end-to-end tests live in `tests/e2e/` and run with `npm run test:e2e`; engine fixtures live in `tests/fixtures/`. The Godot test runs only when `GODOT_BIN` is set.
- `.github/workflows/ci.yml` runs on every pull request; `.github/pull_request_template.md` lists the checks.
